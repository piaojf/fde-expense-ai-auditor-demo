## 待解决的问题

### 1. 尚未授予项目级开源许可证

根目录没有 `LICENSE`，GitHub 许可字段为空，README 与 ASSETS.md 明确说明尚未授予开源许可证。因此目前应称为公开可读的代码项目，不能默认向使用者承诺通常开源许可证包含的复制、修改和再分发授权。需要项目所有者确认代码和资产权利后选择许可证；本次未替所有者选择或授予许可证。参见 [GitHub 的许可证说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)。

### 2. 私密漏洞报告入口与安全策略缺失

本次读取 GitHub 设置，私密漏洞报告为关闭状态；仓库没有 `SECURITY.md`。涉及发票、员工和财务工作流的报告可能包含敏感信息，不能依赖公开 Issue 传递这些资料。建议维护者先确定私密报告渠道，再补充支持版本与安全报告说明。本次未更改仓库的安全设置。

### 3. 手动 Release 发布路径仍未实际验收

[发布工作流](../.github/workflows/release.yml)保留了版本标签校验、重新运行 CI、归档和校验和生成步骤，但此次没有创建标签或 GitHub Release。现有 CI 成功不能替代首次实际发布包的安装与归档验收；准备发布正式版本时仍需检查源码包、前端包和 SHA-256 文件。

## 功能与部署范围限制

- **公开默认路径是基础 Mock。** 完整企业住宿/P4B 仍绑定未分发的私人制度原件；[测试范围清单](../tests/public_scope.json)保留相应排除项，不能把排除项记为通过。README 已说明企业截图不能等同于公开版开箱即用。
- **基础 Mock 不能作为公网财务服务入口。** 在隔离的内存测试中，无会话访问 `GET /claims` 返回 200；基础人工复核 DTO 包含客户端提供的 `reviewer_id`。这与本机演示的设计一致，但不能用作真实身份或财务授权。参见 [基础 API](../apps/api/main.py)、[复核 DTO](../domain/schemas.py) 与 [复核处理](../apps/api/workflow.py)。企业模式另有会话、角色和租户边界；没有对生产部署作验收承诺。
- **真实模型语义质量尚未由公开 CI 验证。** CI 的浏览器流程使用 Mock，不能据此证明真实建议、检索质量或真实 ERP 写入正确。
- **健康检查仅表示存活。** `/health` 的 `database=not_checked` 不能解释为数据库和外部依赖就绪；当前文档已说明该边界。
